# 待外部確認的問題

這些問題要等 MIS 和稽核室回答。在那之前，設計先照「目前假設」進行；答案和假設不同時，再回頭修改。

**風險最大的是 M3 和 M4**，它們決定「每張單都能當稽核證據」這件事能不能成立，建議優先確認。

## 給 MIS

| # | 問題 | 目前假設 | 答案不同時的影響 |
|---|---|---|---|
| M1 | DC 有沒有資料目錄（主題包、欄位、分級、資料擁有者），可以讓本站讀取嗎？ | 有。本站透過可替換的介面讀取；第一版先用匯入檔案代替。 | 小：只換資料來源。 |
| M2 | DC 接受哪種格式的規則？本站要怎麼把規則交過去？ | 本站輸出結構化規則（被授權者、欄位、列條件、起迄、可否匯出）。第一版由 MIS 手動到 DC 套用，套用完在本站按「已套用」才算生效。 | 小：之後可以改成自動交付，流程不變。 |
| M3 | DC 能不能用被授權者的身分做測試查詢？ | 能。系統會自動產生「查得到」和「查不到」的測試案例並執行。 | **大**：做不到的話，自動驗證要改成由 MIS 上傳驗證證據，再由申請人確認。 |
| M4 | 所有存取資料的管道都會經過 DC 嗎？ | 是。 | **大**：有管道可以繞過 DC，那個管道就不受簽核約束。 |
| M5 | DC 能不能區分「查詢」和「匯出」？ | 能，所以申請單有「可否匯出」欄位。 | 小：不能的話就把這個欄位關掉。 |
| M6 | 團隊名單和主管層級從哪裡來（AD、HR 系統）？ | AD 群組加上 HR 的組織樹，透過可替換的介面讀取。 | 中：逾時升級要靠主管層級。 |
| M7 | 手機核准走外網還是一定要 VPN？ | 外網，加上 SSO 和 MFA。 | 小：只影響部署方式。 |
| M8 | SSO 用哪種協定？mail 怎麼寄？ | 透過公司的 AD 做 SSO，mail 透過公司 mail server 寄出。 | 小：只影響串接設定。 |
| M9 | 你們平常維護哪種語言的系統？ | 已採用 Node.js＋TypeScript 實作。 | 中：若 MIS 無法維護，需要改寫後端薄層；SQL function 不受影響。 |
| M10 | 現有的簽核系統要不要跟本站同步？ | 第一版不整合，只預留介面。 | 中：要同步的話，需要另外設計同步規則。 |
| M11 | 資安長和他的代理人是誰？ | 先做成設定，由系統管理員指定。 | 無。 |

## 給稽核室

| # | 問題 | 目前假設 | 答案不同時的影響 |
|---|---|---|---|
| A1 | 紀錄要保存幾年？ | 10 年，可以調整。 | 小：只改設定值。 |
| A2 | 匯出成什麼格式？ | Excel 清單；每張單另有一頁 PDF 證據頁，附上雜湊值。 | 小。 |
| A3 | 每次狀態變更會記下誰、何時、依據哪條規則、改了什麼。這樣夠嗎？ | 會再加記 IP 和裝置。 | 小。 |
| A4 | 稽核的唯讀權限可以看到哪些單？ | 全公司所有的單，包含已撤銷和已到期的。 | 小。 |

## 待使用者提供

- 3–5 張真實申請案例（可去識別化），作為驗收用。
