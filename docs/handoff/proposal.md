## 怎麼重做

1. 建起系統（root，repo 根目錄）：`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers tools/run-all.sh --keep`。這次的結果：資料庫測試 285 全過、對照組 16 全過、端對端 32 全過；頁面在 3001。系統跑完後保持執行。
2. 擷取（`capture.mjs`）：以 `SGN_DATABASE=sgn_e2e` 執行（**一定要設**：不設時 `loadConfig()` 預設指向 `sgn_test`，讀錯通行金鑰檔，簽核人的虛擬驗證器沒有金鑰，核准會一直卡住）。腳本做的事：
   - 直接 import `e2e/tests/lib/ui.mjs`（登入、填單、做決定）；啟動瀏覽器後把 `browser.newContext` 包一層，加上 `deviceScaleFactor: 2`（390×844）。
   - 簽核人沿用 `system-delivery.test.mjs` 的 `signer` 做法：把端對端測試存下的金鑰（`.run/passkeys-sgn_e2e.json`）放回虛擬驗證器，不重新登記。
   - 流程：林怡君（p04）替 `sales-report-bot` 申請銷售訂單（北區、三個欄位、資料期間用一個沒用過的年份，這次是 2033）→ 陳建宏（p03）→ 張美玲（p11）→ 資安合規檢查（p18 認領）→ 交付程式自動送到 sim/dc 並驗證 → 申請人確認 → 縮小（拿掉訂單金額）→ 稽核黃淑芬（p22）看首頁與證據頁 → 申請人撤銷。
   - 截圖：`page.screenshot({ type: 'jpeg', quality: 80, scale: 'css' })`，輸出寬 390 的 JPEG。
   - 重疊提示：另開一張試填的單，資料期間 2026、多勾客戶編號（和端對端留下的生效單部分重疊），只截圖不送出。
   - 「被擋下」：(a) 申請人打開自己的單只有「撤回」，並以同一個工作階段直接呼叫 `/api/challenge_issue`，回 403 `SELF_APPROVAL`；(b) 用 CDP `WebAuthn.setUserVerified(false)` 模擬指紋沒通過，畫面顯示「沒有完成通行金鑰驗證」。
3. 補拍稽核頁展開「檢查了什麼」的畫面（`audit-detail.mjs`，同一張單）。
4. 組頁（`build.mjs`）：讀 `proposal.src.html`、`shots.json`（每張圖的階段、標題、「保護了什麼」、替代文字）、`loop.svg`，把圖換成 data URI 寫到 `docs/site/proposal.html`；之後執行 `npx prettier --ignore-path /dev/null --write docs/site/proposal.html`。
5. 驗證（`verify.mjs`）：Playwright 以 390 寬、淺色與深色各開一次，量 `scrollWidth`（兩種都是 390，沒有水平捲動）、超出視窗的元素（0）、沒載入的圖（0），並分段存整頁截圖人工看過。`npx prettier --check docs/site/proposal.html` 通過；注意 `.prettierignore` 排除了 `docs/`，所以這個指令一定通過，真正的格式檢查要加 `--ignore-path /dev/null`（也通過）。

## 頁面用到的截圖（依頁面順序）

申請：勾欄位、級別與路徑、部分重疊要填理由、申請人只能撤回（被擋 1）。簽核：主管待簽清單、決定畫面、裝置驗證沒過（被擋 2）、確認面板（單號與內容指紋）、資安合規檢查認領。交付與驗證：首頁「等你確認」、自動驗證正反例。生效中：交付紀錄與縮小／撤銷入口、縮小面板、縮小後的差異。收回：撤銷面板、撤回規則完成。稽核：首頁（背景程式狀態）、例外清單、紀錄鏈驗證（展開）、事件紀錄。

拍了沒用：申請人首頁（被舊單塞滿，資訊量低）、核准後回到待簽清單、撤銷後的單頂部、稽核首頁背景程式區（與首頁那張重複）。

## 沒截到或沒用實機畫面的

- **到期後的狀態**：到期要等授權迄日或以管理者連線改資料模擬；這次只示範撤銷（同一條撤回路徑），頁面用文字說明到期。
- **定期複查、稽核資料包、例外處理畫面、管理畫面**：還沒做，頁面標為規劃中。
- **例外清單裡的單**是端對端測試留下的（對帳多出權限、交付被拒、回報不對），不是這張示範單；圖說已寫明。
- **系統管理人人工執行**：這次走系統對系統交付，人工退路只在文字提到。

## 看到的產品問題（沒改，交給負責畫面的人）

1. 稽核證據頁的單據摘要下方出現「nullnull」字樣。
2. 稽核人員首頁最上面是「我的申請／你還沒有申請」，查單與例外被推到下面；簽核人首頁的待簽清單依單號由小到大，新單在最下面。
3. 例外清單：同類例外重複列出、已結案與未結案混在一起，前綴是內部分類（「治理角色・治理例外」），沒有處理或篩選入口。
4. 縮小與撤銷的面板寫「原因（必填，申請人會看到）」，申請人自己操作時這句話不通。
5. 每次打開新申請畫面就存成一張帶單號的草稿，沒有刪除入口；清單會累積、單號跳號。
6. 重疊提示只列單號與期間，沒有直接寫出重疊的是哪些欄位（簽核人那邊會看到）。
