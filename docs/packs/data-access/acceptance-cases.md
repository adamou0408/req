# 資料授權流程包：驗收案例

五個端對端案例，用來驗收 [contract/02-pack-data-access.md](../../contract/02-pack-data-access.md)（以下稱「契約」）。規則的來源是 [rules.md](rules.md)。

## 0. 怎麼讀這份文件

- 人員、主管關係、角色、被授權者用 [contract/seed-directory.md](../../contract/seed-directory.md)，不另外發明人物。
- 基準日是 2026-11-10（星期二）。每一步都寫了假時鐘的時間（台北時間）；執行時先把 `sgn.fake_now` 設成該時間再操作。
- 「畫面」用骨幹第 10 節的通用畫面名稱。資料範圍的輸入與規則的顯示是流程包的專屬元件（契約 §2.4），嵌在通用畫面裡。
- 「排程」那幾步的執行者是系統：把假時鐘設到該時間後執行一次排程。
- 「預期的稽核事件」用文字描述事件，括號裡是事件要記下的規則代碼。事件的動作代碼以 `01-kernel.md` 為準；規則代碼以契約 §7.3 與骨幹第 5 節為準。
- 每個案例彼此獨立：都從第 1 節的種子資料開始（重建資料庫、載入種子），可以單獨執行或依任意順序執行。因此每個案例新建的第一張單，單號都是 `DA-2026-0004`（假設單號格式是「DA-年度-流水號」、每年從 0001 起算；格式由核心決定，不同時以實際單號為準）。
- 端對端執行時使用 `sim/` 的模擬環境（骨幹第 12 節）：帳號來自 LDAP 的種子名單；「收到通知」以 SMTP 模擬器實際收到的信為準；「到 DC 套用規則」是把下載的規則檔匯入 DC 模擬器；自動驗證是對 DC 模擬器真的執行查詢。
- 資料庫層的同一組案例在 `db/tests/packs/data_access/200`–`240`（契約 §10.2），DC 的部分以資料庫測試的輔助 function 代替。

工作天的算法：和時限有關的步驟，時間都選在不論核心用「滿幾個工作天的同一時刻」或「第幾個工作天結束」計算，結果都相同的時點。

| 驗收期間的日期 | 星期 |
|---|---|
| 2026-11-10、11、12、13 | 二、三、四、五 |
| 2026-11-16、17、18、19、20 | 一、二、三、四、五 |
| 2026-11-23、24、25、26、27 | 一、二、三、四、五 |
| 2026-11-30、12-01、02、03、04 | 一、二、三、四、五 |

### 1.5 DC 模擬器的資料

DC 模擬器要有四個主題包對應的資料表與欄位，並且讓契約 §5.11 產生的每個測試查詢都有對應的資料列：每個 `enum` 列條件欄位的每個值至少一筆；`sales_order` 在 2023-12-31、2024-01-01、2024-12-31、2025-01-01 各至少一筆（每個區域都要有）；`payroll` 在 2025-12-31、2026-01-01 各至少一筆。被授權者在 DC 模擬器上的帳號名稱與 seed-directory.md 的被授權者名稱相同。
