# 決策紀錄

資料授權簽核網站的需求與設計決策。這份文件只記錄「目前的結論」，不保留版本差異。

## 目標

- 加速人與人之間的資料授權簽核，減少重複申請。
- 每張單都能直接當稽核證據。
- 背景：上櫃公司，須符合內控準則第 9 條與資通安全管控指引。

## 不做的事

- **不執行權限**：核准結果輸出成規則，由 DataCentric（DC）套用。
- **L1、L2 不走申請**：依規則自動給，本站只處理 L3、L4。級別逐環境判定：某一欄在測試區因已遮罩或去識別而降到 L1、L2 時，測試區的這一欄自動給，正式區的同一欄仍照原級別申請。（2026-11-21 由負責人確認，決策 D96。）
- **申請單不記錄「媒介」**：簽核的對象是資料本身。不論資料從 BI、API、查詢工具或 agent 出去，套用的都是同一條規則。前提是所有存取管道都經過 DC（見 [open-questions.md](open-questions.md) M4）。環境（測試區、正式區）是「哪一份資料」，不是媒介。要匯出時另外調查目的、頻率與方法：目的與頻率供簽核人判斷並進入簽的內容；方法只做統計與送審前的引導，不進簽的內容，也不影響套用的規則。（2026-11-21 由負責人決定，決策 D97。）

## 四個方向原則

其他細節都從這四條推出來。

| # | 原則 | 內容 |
|---|---|---|
| ① | 一律從嚴 | 「簽得快」和「管得嚴」衝突時選管得嚴，L3、L4 用同一套規則；速度靠預填、沿用前案和介面設計來補。 |
| ② | 每關不同人 | 同一張單上，每一關都必須是不同的人，也不能是申請人；代理人也一樣。 |
| ③ | 縮小免簽、擴大就重簽 | 縮小範圍或期間只需通知；任何擴大都從第一關重簽。 |
| ④ | 沒人負責就失效 | 每一筆有效授權，任何時刻都要有一位在職、可問責的負責人。 |

另外三條是從「每張單都能當證據」推出來的：
- **能結構化就結構化**：列條件、使用情境都做成結構化欄位，稽核紀錄加上雜湊鏈。
- **本站管決策、證據和資料目錄，DC 管執行**：生效以 DC 回報套用成功為準；主題包、欄位、分級、擁有者以本站的資料目錄為準，DC 回報它套用的目錄版本，和本站不一致就不生效。（2026-11-21 由負責人決定並授權修改，決策 D92、D96。）
- **人做決定，系統只執行**：每一筆狀態變更都要對得到一個可問責的人。系統自動做的動作（判定級別、查重複、分派、催辦、升級、自動撤銷、到期失效），紀錄上要寫明依據哪條規則；這些控管規則由 **MIS** 負責，只有 MIS 系統管理員能修改設定，修改也會留紀錄。泳道圖只畫人的泳道，系統步驟畫在負責人的泳道裡。

## 角色

| 角色 | 說明 |
|---|---|
| 申請人 | 提出申請、確認驗證結果；不能簽自己的單。 |
| 申請人主管 | 第一關。 |
| 資料擁有者 | 依主題包決定；一張單有多位擁有者時並行簽，全部核准才往下一關。 |
| 資安長 | 只在 L4 出現；指定一人，可設代理人。 |
| MIS | 資安合規檢查＋執行設定；單子進 MIS 群組的待辦，由組內一人認領。 |
| 稽核 | 唯讀，可查詢全公司所有的單並匯出。 |

## 簽核路徑

| 級別 | 路徑 |
|---|---|
| L3 | 主管 → 資料擁有者（並行）→ MIS |
| L4 | 主管 → 資料擁有者（並行）→ 資安長 → MIS |

- 一張單同時有 L3、L4 欄位時，整張照 L4 走。
- L1、L2 欄位會自動從單上移除，並提示「這些欄位自動給」。

### 職責分離（原則 ②）

- 同一張單上，每一關都必須是不同的自然人，也不能是申請人。撞到時自動改由上一層主管簽。
- 申請人本身是主管時，主管關直接給他的上一層主管。
- 代理人簽核時一樣要遵守這條；紀錄會寫明「誰代誰簽」。

### 逾時

- 每關超過時限未簽，先催辦；再超過時限，升級給該簽核人的上一層主管。
- 升級後只有升級對象能簽，原簽核人不能再簽。
- 所有關卡都適用；天數做成設定。

## 修改、退回與撤銷（原則 ③）

| 情況 | 處理 |
|---|---|
| 簽核人修改 | 只能縮小資料範圍、授權起迄或資料期間；縮小後通知申請人，不用重簽。 |
| 退回後，申請人只做縮小 | 從退回的那一關繼續簽。 |
| 退回後，申請人做其他修改 | 從第一關重簽。修改使用情境也算擴大。 |
| 一鍵續期 | 預填前案，仍走完整路徑；畫面標示「與前案差異」。 |
| 撤銷 | 等於縮小到零，所以申請人、負責人、任一位簽核人、MIS 都可以直接撤銷，不需要簽核，但必須填原因。 |

## 被授權者（原則 ④）

- 只能是「團隊或專案」或「AI agent／服務帳號」，不直接授權給個人。
- **團隊**：讀取組織資料；團隊解散時，相關授權自動撤銷。
- **專案**：任何人都可以在本站建立，但必須指定負責人和結束日。建立時系統會比對名稱相似的專案並提示。專案本身不帶任何權限；專案結束時，相關授權自動失效。
- **agent**：必須指定一位負責人。
- **代填申請**：任何人都可以替團隊、專案或 agent 填單；但申請人不是該被授權者的負責人時，第一關先由負責人確認，確認後才往下送。負責人自己申請時不加這一關。負責人確認也受原則 ② 約束。（2026-11-20 由負責人核准新增；起因見 `redteam/findings-3.md` 低-2、決策 D79。）
- **負責人離職或調職**：通知他的主管在寬限期內改指派負責人，逾期自動撤銷。

## 需求單

### 欄位

| 欄位 | 說明 |
|---|---|
| 資料範圍 | 主題包 → 欄位 → 列條件。列條件是結構化的，例如「區域 in（北、中）」，不開放自由寫 SQL。 |
| 資料期間 | 資料本身的時間範圍，例如「只能看 2024 年的訂單」。屬於列條件的一種，交給 DC 套用。 |
| 環境 | 測試區或正式區，必填；一張單只有一個環境。見下方「環境」。 |
| 被授權者 | 團隊、專案或 agent。 |
| 授權起迄 | 權限有效的日期。申請人自填，簽核人只能縮短；各級別有上限。 |
| 使用情境 | 分類下拉＋文字說明。 |
| 可否匯出 | 「查看」和「帶走」分開；L4 預設不可匯出。若 DC 無法區分，這個欄位就關閉（見 M5）。 |
| 驗證結果 | 由系統自動測試，加上申請人確認。 |

使用情境的分類（可在後台調整）：報表與分析、系統開發或測試、AI 模型訓練或推論、稽核或法遵查核、客戶服務或營運作業、其他（需說明）。

### 環境

（2026-11-21 由負責人決定並授權新增，決策 D93、D96。）

- 申請的資料分測試區與正式區。測試區的核准不能拿到正式區用，升到正式區是另一張單。
- 級別由資料目錄逐欄、逐環境決定：測試區預設與正式區同級；目錄標示該欄在測試區已去識別或遮罩時，才用那一區的分級。申請人不能自稱。
- 交付的規則帶環境；DC 證明套用到哪一區，和規則不同就不生效。自動測試另外確認同一份規則在另一區查不到。重疊、對帳與使用紀錄都分區。
- 正式區的單必須引用一張涵蓋它的測試區單（同一位申請人或同一個被授權者、主題包與欄位涵蓋、列條件不比它窄、曾經生效）。沒有時要填理由，送出後開例外，簽核人看得到；核准生效後，申請人要在期限內補上線後的使用報告，逾期升級，不撤銷。

### 測試報告

（2026-11-21 由負責人決定並授權新增，決策 D94、D96。）

- 正式區的單引用測試區單時，系統從那張單的使用紀錄產生測試報告，送出時凍結，簽核人簽的內容包含它。報告列出：測試了什麼、實際用了什麼（逐欄次數與最後使用時間）、沒用到的欄位、被擋下的嘗試、與這次申請的差異、應用面（申請人填：程式或報表與版本、結果給誰看、每欄用途）、紀錄完整性。
- 系統自動標警示：有沒測過的欄位、沒用到的欄位仍在申請裡、測試期間有被擋下的嘗試、測試量低於門檻。
- 應用面的版本以 DC 回報的為準，沒有才用申請人填的；版本和測試時不同時，L4 要重新測試，L3 提示。

### 重複申請

- 被既有有效授權**完全涵蓋**：直接擋下。
- **部分重疊**：必須填寫理由，簽核畫面會標示重疊的部分。

### 狀態

```
草稿 → 送審 → 逐關核准（或退回）→ 待套用 → 驗證中 → 生效 → 到期／撤銷
```

- **待套用**：MIS 核准後，等 DC 回報套用成功。
- **驗證中**：系統自動測試「查得到該查的、查不到不該查的」，再由申請人確認。兩者都通過才結案生效。
- 自動測試沒過，退回 MIS 修正設定。
- 申請人逾期沒有確認驗證結果，自動撤銷。

## 加速功能（第一版都要）

| 功能 | 規則 |
|---|---|
| 沿用前案或範本 | 新申請可以從空白、前案或範本開始。 |
| 一鍵續期 | 見上方「修改、退回與撤銷」。 |
| 批次核准 | 每張單各自留一筆核准紀錄；批次畫面上每張單都要顯示差異摘要。有「擴大」或「重疊警示」的單不能放進批次。 |
| 手機核准 | 透過 SSO 登入；核准時要多一道驗證（MFA），L3、L4 都一樣。 |

## 時間規則

- 授權起迄和資料期間分開存。
- 到期前提醒；到期自動失效。

### 預設時限（「標準」組，全部可設定）

| 項目 | 預設值 |
|---|---|
| 催辦 | 每關 3 個工作天未簽 |
| 升級 | 催辦後再 2 個工作天未簽 |
| 授權上限 | L3 一年、L4 半年；測試區 3 個月 |
| 沒有測試紀錄就上線，補使用報告的期限 | 20 個工作天 |
| 測試量門檻 | L3 10 次、L4 20 次 |
| 到期前提醒 | 14 天 |
| 負責人異動寬限期 | 14 天 |
| 驗證結果確認時限 | 5 個工作天 |
| 紀錄保存年限 | 10 年（待稽核室確認，見 A1） |

## 稽核證據

- 每次狀態變更都記下：誰、何時、依據哪條規則、改了什麼，以及 IP 和裝置。
- 紀錄只增不改，並加上雜湊鏈，讓竄改可以被偵測。
- 稽核可以唯讀查詢全公司所有的單；匯出格式為 Excel 清單，每張單另有一頁可列印的 PDF 證據頁（待稽核室確認，見 A2）。

## 整合

現有簽核系統、人員與組織資料來源都做成可替換的介面。第一版先以獨立網站＋SSO＋mail 通知設計。

## 技術

- PostgreSQL；商業邏輯全部放在 SQL function，前端只負責呈現。
- 中間一層很薄的後端，只負責傳話和對外工作（SSO、mail、與 DC 交換規則、自動驗證）。採用 Node.js＋TypeScript；前端採用 React＋TypeScript。
- SSO、mail、DC、人員與組織資料都做成可替換的介面，先接模擬版本；真實系統待 MIS 確認後再串接。
- 驗收先用 5 個模擬案例，見 [acceptance-cases.md](acceptance-cases.md)。
- 地端部署；上線範圍為全公司。
