# 驗證案例的選擇

用哪些案例來驗證平台，決定了平台有沒有說服力。這份文件記錄候選案例、判斷標準和選擇結果。法規條號以 `docs/research/` 的調查結果為準；這裡只寫方向。

## 判斷標準

| 標準 | 問題 |
|---|---|
| 普遍 | 是不是每家公司都有這件事？ |
| 稽核壓力 | 稽核是不是每年都會查？出事的後果重不重？ |
| 驗證到新的能力 | 這個案例會不會用到別的案例沒用到的平台能力？ |
| 可以實測 | 能不能在模擬環境裡用真的系統跑過？ |

## 兩個層次

- **同一種流程的不同資料領域**：驗證這個流程夠不夠強。例如人資薪資、財會資料、客戶個資，都是「資料授權」。
- **不同種類的流程**：驗證平台是不是真的通用。例如資料授權、程式變更上線、合約用印，結構完全不同。

兩個層次都需要。只有第一層，證明不了通用；只有第二層，每個流程都太淺。

## 資料授權流程包的資料領域

| 資料領域 | 為什麼有說服力 | 級別 | 會特別驗證到 |
|---|---|---|---|
| 人資：薪資、考績、健康檢查 | 每家公司都有；外洩的後果是員工直接受害；健康檢查屬於法律特別保護的個資 | L4 | 申請單本身也要保密（連 MIS 都不該看到薪資申請的細節）；誰看過這張單要留紀錄 |
| 財會：尚未公告的財務報表、總帳 | 上市櫃公司最敏感的資料；公告前屬於內線資訊，公司要掌握誰知悉 | L4，公告後降級 | 依事件到期（財報公告日一到，授權自動失效或降級）；知悉人員名單 |
| 客戶：個資、合約、交易 | 個資法；業務單位最常申請 | L3–L4 | 列條件（只看自己區域）、欄位層級 |
| 營運：銷售、成本、毛利 | 最常見的分析需求 | L3–L4 | 重疊檢查、續期、批次 |
| AI agent 與服務帳號取用上述資料 | 新興需求，現有工具多半沒管到 | 依資料 | 必須有負責人；負責人異動 |

## 其他流程類型的候選

| 流程 | 誰在意 | 稽核壓力 | 驗證到的平台能力 | 評估 |
|---|---|---|---|---|
| **系統帳號與角色權限** | 資訊、稽核 | 很高：資訊系統稽核每年必查 | 職責衝突矩陣（例如同時能建供應商和核准付款）、到職調職離職、定期複查 | 稽核價值最高；結構和資料授權相近 |
| **程式變更上線** | 資訊、稽核 | 很高：和存取控制並列的必查項目 | 一次性流程；開發的人不能自己核准和上線；上線後驗證；緊急變更先做後審 | 稽核價值高，而且結構和資料授權差很多，最能證明通用 |
| **特權帳號與緊急權限** | 資訊、資安 | 高 | 以小時計的有效期間；緊急情況先給後審；事後強制複核 | 可以併入「系統帳號與角色權限」 |
| **供應商銀行帳號變更** | 財會 | 高：詐騙的常見手法 | 由獨立的人回撥確認（人工的獨立驗證）；變更內容的前後對照 | 非資訊領域中最有說服力；規模小 |
| **付款與請款核決** | 財會 | 高 | 核決權限表（金額乘上類別決定簽到哪一層）；重複付款檢查 | 很普遍，但 ERP 多半已內建，市場缺口較小 |
| **合約用印** | 法務、總務 | 中 | 一次性流程；依金額分級；附件 | 台灣常見；規模小，適合當最小的示範 |
| **委外人員與廠商的帳號** | 資訊、採購 | 中到高 | 外部人員一定要有內部的負責人；合約到期自動失效 | 可以併入「系統帳號與角色權限」 |
| **個資對外提供或跨境傳輸** | 法務、個資窗口 | 中到高 | 資料離開公司的核准與紀錄 | 可以併入資料授權的「可否匯出」 |

## 選擇結果

五種流程都納入第一版（決策紀錄 D13）。它們不是同時上線給使用者，而是同時用來驗證平台：

| 流程 | 在驗證中的角色 |
|---|---|
| 資料授權，含人資、財會、客戶、營運四個資料領域與 AI agent 情境 | 第一個實際要上線的流程；人資與財會最有說服力 |
| 程式變更上線 | 稽核必查；結構和資料授權差異最大 |
| 系統帳號與角色權限（含特權、緊急、委外人員） | 稽核必查；職責衝突矩陣、定期複查、緊急路徑 |
| 供應商銀行帳號變更 | 財會的說服案例；人工的獨立驗證 |
| 合約用印 | 完全用宣告方式定義、不寫任何程式的流程，證明客戶可以自己新增流程 |

資料授權、系統帳號與角色權限、程式變更上線三者合起來，就是資訊系統稽核最主要的查核範圍。

## 這些案例帶出的核心能力

| 能力 | 由哪個案例帶出 | 納入時機 |
|---|---|---|
| 申請單保密：內容只有當事人與該關簽核人看得到；清單上遮蔽；稽核查閱要留紀錄 | 人資薪資 | 第一版 |
| 查閱紀錄：誰在什麼時候看過哪張單 | 人資薪資、財會 | 第一版 |
| 依事件到期：授權在某個事件發生時失效或降級（公告日、專案結束、離職、合約到期） | 財會、委外人員 | 第一版 |
| 知悉人員名單：某一類資料在某段期間內有誰能看 | 財會 | 第一版（由授權查詢與證據輸出提供） |
| 人工的獨立驗證：由沒有參與的人確認執行結果 | 供應商銀行帳號變更、程式變更 | 第一版 |
| 緊急路徑：先執行、限時內補簽核與複核，逾期自動收回並列為例外 | 特權與緊急權限、緊急變更 | 第一版 |
| 職責衝突矩陣：同一主體不得同時持有互相衝突的授權 | 系統帳號與角色權限 | 第一版 |
| 核決權限表：依金額與類別決定簽到哪一層 | 合約用印、供應商銀行帳號變更 | 第一版 |
| 宣告式的流程定義：分級、縮小方向、重複判斷不寫程式就能設定 | 合約用印 | 第一版 |
| 設定變更走簽核：流程、路徑、參數、角色指派的修改都要雙人覆核 | 全部 | 第一版 |
