# UI/UX 驗收標準

這個產品的目的是「<產品要讓使用者做到的事>」，所以畫面好不好用是驗收的一部分。以下任何一項不通過，就不算完成。

## 1. 原則

- **手機優先**：<主要使用者>主要用手機。每個畫面先在 390px 寬設計，再放大到電腦。（主要裝置不同時改寫。）
- **先給結論**：使用者打開一個畫面，第一眼就要看到做決定需要的事實，不用捲動、不用點開。
- **少填、少點**：能預填的不讓人填；能一步完成的不拆成兩步。
- **說人話**：畫面上不出現系統內部的用語（代碼、資料表名稱、英文錯誤訊息）。

## 3. 每個畫面都要通過的檢查

自動檢查（寫在端對端測試裡，每個頁面在手機和電腦兩種寬度都跑）：

- 390px 寬沒有水平捲動。
- 可點擊的元素至少 44×44px。
- 無障礙掃描（axe-core）沒有 serious 或 critical 等級的問題。
- 文字對比達到 WCAG AA。
- 只用鍵盤可以完成任務，焦點位置看得見。
- 每個輸入欄位都有對應的標籤。

人工檢查（由獨立的審查者逐頁看截圖）：

- 有「載入中」「沒有資料」「發生錯誤」三種狀態，而且各自說明接下來可以做什麼。
- 錯誤訊息說明哪裡錯、怎麼修正。
- 會造成影響的動作（刪除、撤銷、退回、核准）有確認步驟，並說明後果。
- 同一個概念全站用同一個詞；狀態的顏色與文字一致，而且不只靠顏色區分。
- 版面在手機上不擁擠，重要資訊在上面。
- 操作後有即時回饋；清單與詳情之間來回不會迷路。

## 4. 驗收流程

1. **自動檢查**：端對端測試包含第 3 節的自動檢查，以及第 2 節每個任務的步數。
2. **獨立審查**：每個角色各由一位沒有參與實作的審查者，依 Nielsen 十項易用性原則和第 3 節的人工檢查，看著真實畫面的截圖逐頁審查。發現的問題依嚴重程度修正後重新審查。
3. **使用者驗收**：產出一頁 HTML 的畫面走查，包含每個任務在手機和電腦上的逐步截圖。由專案負責人看過並確認；有意見就修正後更新同一頁。

第 3 步的確認是最終依據。前兩步通過，只代表可以送交驗收。
