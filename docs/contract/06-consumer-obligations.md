# 使用方系統的義務清單

給開發使用方系統（資料平台 DC，以及之後任何實際擋下存取的系統）的人照著做。依據：裁決 D91 (4)。

這份文件**只列義務並指向契約**，不重寫格式與演算法；格式、欄位、狀態碼一律以「契約依據」欄指到的位置為準。兩邊寫法不同時，以被引用的文件為準，並回報這份清單要修。

## 0. 怎麼讀

| 欄 | 意思 |
|---|---|
| 義務 | 使用方系統必須做到的一件事，可以用測試驗證 |
| 為什麼 | 少了它，閉環的哪一段會斷 |
| 契約依據 | 格式與行為寫在哪裡。`05`＝[05-integration.md](05-integration.md)；`02`＝[02-pack-data-access.md](02-pack-data-access.md)；`README`＝`sim/dc/README.md`；`增修`＝[pending-amendments.md](pending-amendments.md) 的「D91 的契約增修」 |
| 平台 | **已實作**／**有契約**（契約有、平台還沒做）／**無契約**（契約也沒有，已寫進增修，定案前不要照做） |
| 驗收 | `sim/dc/tests/` 的哪個檔案已示範，平台這邊哪個測試對著它跑（測試名稱以規則代碼開頭）。`—` 表示還沒有示範 |

平台測試的簡稱：`50`＝`db/tests/packs/data_access/50-delivery.test.mjs`；`60`＝`…/60-catalog-version.test.mjs`；`65`＝`…/65-capability.test.mjs`；`70`＝`…/70-usage.test.mjs`；`75`＝`…/75-environment.test.mjs`；`93`＝`db/tests/kernel/93-delivery-adapter.test.mjs`（對著執行中的 sim/dc）；`e2e`＝`e2e/tests/system-delivery.test.mjs`。

閉環的九個環節：

```
核准 → ① 收規則與驗章 → ② 執行 → ③ 回應證明 → ④ 驗證查詢 → 生效
                                                        ↓
⑨ 目錄對照版本 ← ⑧ 身分對應 ← ⑦ 撤回與封存 ← ⑥ 使用紀錄 ← ⑤ 對帳清單
```

## 3. 模擬器與真實系統的差別

`sim/dc` 是這份清單的示範實作，但有三件事真實系統不能照抄：

- 管理後門（README「管理後門」）只供測試，真實系統不得存在。
- 傳輸沒有加密（`docs/handoff/redteam-fixes-4.md`）；真實系統必須用 TLS。
- 回應的證明不防使用方系統自己說謊；那由對帳（⑤）與使用紀錄（⑥）事後抓。

真實 adapter 的驗收方式依工程規範第 5 節：對著真實系統跑過 `93` 這一份合約測試。
