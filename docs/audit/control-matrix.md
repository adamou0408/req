# 控制對照表

法規與稽核實務 → 控制目標 → 稽核要的證據 → 平台怎麼做到 → 哪個測試證明。依據來自 [docs/research/](../research/)（綜合見 [00-synthesis.md](../research/00-synthesis.md)）；平台做法引用 [contract/00-spine.md](../contract/00-spine.md) 的規則代碼與實體。

- 建立日期：2026-11-19；對照的骨幹版本：00-spine.md 與 pending-amendments.md 當日內容。
- 「缺口」：骨幹還沒有的部分，寫明需要什麼；已列在 [pending-amendments.md](../contract/pending-amendments.md) 的標出編號，沒有列的標「新」。依 A9，契約總修訂時逐列核對。
- 「預計的測試」：`db/tests/kernel/`（資料庫規則）、`db/tests/packs/<代號>/`、`e2e/`（端對端，含稽核角色），整合測試一律對 `sim/` 的真實協定環境（D5）。每項控制至少有一個「試著繞過」的測試。

**依據的標記**

| 標記 | 意義 |
|---|---|
| 〔強〕 | 對括號內的適用對象有明文的強制規定 |
| 〔業〕 | 業別規範，主管機關檢查時據以開立缺失 |
| 〔建〕 | 建議性質的指引或自願框架 |
| 〔實〕 | 稽核實務、主管機關裁處或檢查結果、審計統計 |
| 〔推〕 | 由條文或實務推論 |

條文出處的簡稱：處理準則＝公開發行公司建立內部控制制度處理準則；指引＝上市上櫃公司資通安全管控指引（2026-11-09 版條次）；附表十＝資通安全責任等級分級辦法附表十（公務機關與特定非公務機關）；證券期貨指引＝證券暨期貨市場各服務事業資通系統安全防護基準參考指引；金控銀行辦法＝金融控股公司及銀行業內部控制及稽核制度實施辦法。ISO/IEC 27001／27002 與 SOC 2 的原文未取得，本表不引用（00-synthesis U3）。

**平台不保證的部分**（D10）：公司是否照規定使用平台、外部系統是否照核准設定、特權帳號在各系統內的操作內容。平台以對帳（C-41）、受管系統涵蓋（C-42）與例外（C-36）讓它們提早浮現。
