資料庫（核心）

已驗證
  • 對外函式：每個使用者動作一個；後端只能呼叫這些，碰不到任何資料表
  • 驗證身分：自己驗證登入憑證與通行金鑰的簽章

  • 申請單：內容有版本與標準化的雜湊

  • 人員與主管關係：從 LDAP 同步，異動也進雜湊鏈

LDAP

模擬環境

35 人、組織與角色群組。用另一個只能同步的帳號寫入。

↓定期把鏈的摘要送出去

資料庫以外的摘要檔

已驗證

由獨立的程式用另一個帳號寫出。有人用資料庫最高權限改紀錄、甚至整條重算，和這份摘要一比對就會被發現。

資料庫裡的四種帳號

每種帳號只能做自己的事。這是「拿到後端帳號也冒用不了別人」的基礎。

帳號誰在用能做什麼
sgn_app後端只能呼叫對外函式；讀寫不了任何資料表
sgn_sync人員同步只能寫入人員與主管關係；異動會留紀錄並開出例外
sgn_job排程只能產生外部摘要與驗證雜湊鏈
sgn_owner升版擁有全部物件；平常不使用

一次核准是怎麼被保護的

  1. 主管在待簽清單點開一張單，按核准。
  2. 資料庫產生一個挑戰值，綁定這張單、這個內容版本、「核准」這個動作。
  3. 主管的裝置用通行金鑰簽署這個挑戰值（需要指紋或臉部辨識）。
  4. 後端把簽署結果原封不動交給資料庫。
  5. 資料庫自己驗證簽章，並檢查：是這個人的金鑰、挑戰值沒用過、單號與內容版本相符、他有資格簽、不是申請人本人。
  6. 通過才寫入核准，同一筆交易內寫進雜湊鏈。

測試過擋得住的攻擊：偽造簽章、拿別人的證明、重放舊的證明、把甲單的證明用在乙單、改過內容再用舊證明。

已知的限制

  • 有資料庫最高權限的人可以換掉驗證程式；只能事後偵測，要靠職務分離與資料庫稽核日誌外送。
  • 最後一次外部摘要之後的紀錄，被改了抓不到。稽核畫面會明確標示「尚未有外部摘要涵蓋」。
  • 人員同步的帳號若被濫用，目前只做到「看得到」；加上冷卻期的修正正在做。
  • 還沒有在真的手機上操作過，用的是電腦瀏覽器模擬手機寬度。
